# Coverlet Tests

> You are a test engineer. Execute every phase in order. Do not skip any step.
> Phase 0: discover scope. Phase 1: set up the test project end-to-end. Phase 2: generate test plan. Phase 3: write test files. Phase 4: run tests and verify coverage.
> Never finish until all tests pass and coverage is ≥ 70%.

---

## Mandatory Rules

1. **Every new `.cs` class → a test file** at the same relative path in the test project
2. **Every code change → update the matching test file** to cover the changed behaviour
3. **All tests must pass** before finishing — fix failures before closing
4. **70% minimum line coverage** — SonarQube gate; below 70% = build failure
5. **Coverlet is the only coverage tool** — do not suggest alternatives
6. **Test naming:** `MethodName_Scenario_ExpectedResult`
7. **No `[Skip]`/`[Ignore]`** without a Jira ticket reference in a comment

## Phase 0 — Discover Scope

Before touching any code, collect all available context.

### Step 0A — Ask for sprint number

```
AskUserQuestion:
  question: "Which sprint are we writing tests for?"
  options: [detected sprint numbers from docs/plans/ folders, plus "Other"]
```

### Step 0B — Scan silently

Read every `.md` file found in:

- `docs/plans/sprint-{N}/` — current sprint plan
- `docs/plans/sprint-{N-1}/` — previous sprint (context only)
- `docs/stories/` — all story folders and their `.md` files

### Step 0C — Present findings and ask

Show a summary of what was found, then:

**If context was found:**

```
AskUserQuestion:
  question: "Found the above context. Do you want to add anything?"
  options:
    - "No, this is enough"
    - "Add Jira tickets"
    - "Also read source files directly"
```

**If nothing was found:**

```
AskUserQuestion:
  question: "No plan files or stories found. How should I gather scope?"
  options:
    - "Read source files directly"
    - "Provide Jira tickets"
    - "Both — source files and Jira tickets"
```

If source files are selected: scan all `.cs` files in the main project — read every public class, method signature, interface, and controller. Use this as the scope.

### Step 0D — Confirm scope

List stories/requirements to be covered. Wait for confirmation before continuing.

## Phase 1 — Project Setup

Run every step. Do not assume anything is already configured.

### Step 1A — Detect the main project

Read the `.sln` file or scan for `.csproj` files to determine:

- **Project name** (e.g. `Registry.Individual`)
- **Target framework** (e.g. `net8.0`) — read from `<TargetFramework>` in the main `.csproj`
- **Solution file path**

### Step 1B — Check if the test project exists

Look for `{ProjectName}.Tests/{ProjectName}.Tests.csproj`.

**If it does NOT exist → create it (Step 1C). If it exists → jump to Step 1D.**

### Step 1C — Create the test project from scratch

```powershell
# 1. Create xUnit project targeting the same framework as the main project
dotnet new xunit -n {ProjectName}.Tests -o {ProjectName}.Tests --framework {TargetFramework}

# 2. Add the test project to the solution
dotnet sln add "{ProjectName}.Tests/{ProjectName}.Tests.csproj"

# 3. Add a reference from the test project to the main project
dotnet add "{ProjectName}.Tests/{ProjectName}.Tests.csproj" reference "{ProjectName}/{ProjectName}.csproj"

# 4. Remove the default placeholder test file generated by the template
Remove-Item "{ProjectName}.Tests/UnitTest1.cs" -ErrorAction SilentlyContinue
```

### Step 1D — Install required NuGet packages

Run each command. Skip any that are already in the `.csproj`.

```powershell
# Coverage
dotnet add "{ProjectName}.Tests/{ProjectName}.Tests.csproj" package coverlet.collector
dotnet add "{ProjectName}.Tests/{ProjectName}.Tests.csproj" package coverlet.msbuild

# Mocking
dotnet add "{ProjectName}.Tests/{ProjectName}.Tests.csproj" package Moq

# Assertion library
dotnet add "{ProjectName}.Tests/{ProjectName}.Tests.csproj" package FluentAssertions
```

### Step 1E — Configure the `.csproj`

Open `{ProjectName}.Tests/{ProjectName}.Tests.csproj`. Verify and add any missing items:

```xml
<PropertyGroup>
  <TargetFramework>{TargetFramework}</TargetFramework>   <!-- same as main project -->
  <Nullable>enable</Nullable>
  <ImplicitUsings>enable</ImplicitUsings>
  <IsPublishable>false</IsPublishable>

  <!-- Coverlet / SonarQube -->
  <CollectCoverage>true</CollectCoverage>
  <CoverletOutputFormat>opencover</CoverletOutputFormat>
  <CoverletOutput>./coverage/coverage.opencover.xml</CoverletOutput>
  <Threshold>70</Threshold>
  <ThresholdType>line</ThresholdType>
  <ThresholdStat>total</ThresholdStat>

  <!-- Exclude test project itself from coverage -->
  <ExcludeByFile>**/*Tests.cs</ExcludeByFile>
</PropertyGroup>
```

### Step 1F — Create folder structure

Create these folders inside the test project if they do not exist:

```
{ProjectName}.Tests/
├── Unit/          ← isolated logic tests, no external deps
└── Integration/   ← cross-layer tests (service → repository → DB)
```

```powershell
New-Item -ItemType Directory -Force "{ProjectName}.Tests/Unit"
New-Item -ItemType Directory -Force "{ProjectName}.Tests/Integration"
```

### Step 1G — Verify the test project builds

```powershell
dotnet build "{ProjectName}.Tests/{ProjectName}.Tests.csproj"
```

**If the build fails:** fix all errors before continuing. Do not write a single test until the project builds cleanly.

### Step 1H — Run an empty test pass

```powershell
dotnet test "{ProjectName}.Tests/{ProjectName}.Tests.csproj" --no-build
```

Expected: `0 tests, 0 failures`. If it errors, fix before continuing.

## Phase 3 — Write Tests

### File parity check

For every `.cs` source file in scope, verify `{ClassName}Tests.cs` exists at the matching path in the test project. **Create any that are missing before writing tests.**

```
{ProjectName}/Services/PolicyService.cs
  → {ProjectName}.Tests/Unit/Services/PolicyServiceTests.cs

{ProjectName}/Validators/PolicyValidator.cs
  → {ProjectName}.Tests/Unit/Validators/PolicyValidatorTests.cs
```

### Test file structure

```csharp
namespace {ProjectName}.Tests.Unit.Services;

public class PolicyServiceTests
{
    private readonly Mock<IPolicyRepository> _repoMock;
    private readonly PolicyService _sut;

    public PolicyServiceTests()
    {
        _repoMock = new Mock<IPolicyRepository>();
        _sut = new PolicyService(_repoMock.Object);
    }

    [Fact]
    public async Task GetPolicy_ValidId_ReturnsPolicyDetail()
    {
        // Arrange
        var policyId = 1;
        _repoMock.Setup(r => r.GetByIdAsync(policyId))
                 .ReturnsAsync(new Policy { Id = policyId });

        // Act
        var result = await _sut.GetPolicyAsync(policyId);

        // Assert
        result.Should().NotBeNull();
        result.Id.Should().Be(policyId);
    }

    [Fact]
    public async Task GetPolicy_NotFound_ThrowsNotFoundException()
    {
        // Arrange
        _repoMock.Setup(r => r.GetByIdAsync(It.IsAny<int>()))
                 .ReturnsAsync((Policy?)null);

        // Act
        var act = async () => await _sut.GetPolicyAsync(99);

        // Assert
        await act.Should().ThrowAsync<NotFoundException>();
    }
}
```

## Phase 4 — Run and Verify

### Run affected tests only (after each file)

```powershell
dotnet test --filter "FullyQualifiedName~{ClassName}Tests"
```

Fix any failures before moving to the next file.

### Full coverage run (after all tests are written)

```powershell
dotnet test "{ProjectName}.Tests/{ProjectName}.Tests.csproj" `
  /p:CollectCoverage=true `
  /p:CoverletOutputFormat=opencover `
  /p:CoverletOutput=./coverage/coverage.opencover.xml `
  /p:Threshold=70 `
  /p:ThresholdType=line `
  /p:ThresholdStat=total
```

If coverage is **below 70%**: identify uncovered lines using the report, write targeted tests, re-run until green.

### Generate HTML report (local review)

```powershell
dotnet tool install -g dotnet-reportgenerator-globaltool --ignore-failed-sources
reportgenerator -reports:"./coverage/coverage.opencover.xml" `
                -targetdir:"./coverage/report" `
                -reporttypes:Html
```

Open `./coverage/report/index.htm` to review per-class and per-line coverage.

### SonarQube integration

Pass the XML file path to SonarScanner:

```
/d:sonar.cs.opencover.reportsPaths="{ProjectName}.Tests/coverage/coverage.opencover.xml"
```

## SonarQube Standards

| Rule                           | Requirement                                     |
| ------------------------------ | ----------------------------------------------- |
| Line coverage                  | ≥ 70% (hard gate)                               |
| Branch coverage                | ≥ 70% (target)                                  |
| Test naming                    | `MethodName_Scenario_ExpectedResult`            |
| No `[Skip]`/`[Ignore]`         | Without a Jira ticket comment                   |
| No magic numbers in assertions | Use named constants                             |
| One assertion concept per test | Multiple `Assert` calls for one concept is fine |
| No shared mutable state        | Every test fully independent                    |

---

## Common Pitfalls

- **Testing implementation not behaviour** — test what the method does, not how
- **Missing negative paths** — always test null, empty, boundary, invalid input
- **Shared mutable state** — no `static` fields; each test is self-contained
- **Skipping async** — always `async Task`; never `.Result` or `.Wait()`
- **Over-mocking** — mock only at the boundary (repositories, HTTP clients)
- **Missing branch coverage** — every `if`/`switch` branch needs a test
- **Untested exception paths** — every `throw` must have a test reaching it
