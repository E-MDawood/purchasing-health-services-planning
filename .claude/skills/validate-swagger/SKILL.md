# Swagger Validation

> You are an enforcer, not just a reporter.
> Step 1: Read `docs/api/swagger.json`. Step 2: Read `.claude/skills/validate-swagger/data/swagger-rules.json` and validate every rule where `isActive: true`. Step 3: Fix — prefer C# source; if the fix cannot be produced by C#, edit `docs/api/swagger.json` directly. Step 4: Ask before changing anything that affects the API contract.
> Never silently skip a rule.

---

## Swagger File Location

**Standard path (all projects):** `docs/api/swagger.json`

The file is generated by `dotnet build` via Swashbuckle.

---

## Fix Rule

For every violation, apply this rule:

- **Issue can be fixed in C# code** (controller attribute, DTO annotation, Swashbuckle filter) → **ASK** the developer for approval, then apply to C# source.
- **Issue cannot be fixed in C# at all** (e.g. a static metadata value Swashbuckle cannot produce) → **AUTO** fix directly in `docs/api/swagger.json`.

Never edit the JSON for something that has a C# fix — it will be silently overwritten on the next `dotnet build`.

---

## Project Context — Read Before Validating

This is an **ASP.NET Core .NET 8** project using **Swashbuckle**. The following filters are already wired in `Infrastructure/Swagger/SwaggerExtensions.cs` — do not report rules they provably cover:

| Filter / Class | What it already covers |
|---|---|
| `ProblemDetailsOperationFilter` | RFC 9457 `application/problem+json` on error responses; adds 401, 403, 429 |
| `CacheRateLimitOperationFilter` | Cache-Control, ETag, Last-Modified headers; rate-limit headers; 304 on GET/HEAD |
| `IntegerSchemaFilter` | `minimum`/`maximum` on all integer properties |
| `ArraySchemaFilter` | `minItems`/`maxItems` on all array properties |

Before flagging a violation, verify the issue actually appears in the **generated JSON** — these filters may already cover it.

## Fix Policy

### AUTO — Apply immediately, no approval needed
Only pure documentation text and harmless extension properties. Zero impact on the API contract, Apigee routing, or generated clients.

| Rule | Fix target | Where to fix |
|---|---|---|
| `operation-description` | Add/improve `/// <summary>` XML comment | C# controller |
| `parameter-description` | Add/improve `/// <param>` XML comment | C# controller |
| `response-description-quality` | Improve description text | C# XML comment or Swashbuckle filter |
| `endpoint-timeout` | Add `x-timeout` property | New `TimeoutOperationFilter` (C#) or directly in JSON if C# not feasible |
| `language-support` | Add `x-languages` array on string properties | New `LanguagesSchemaFilter` (C#) |
| `examples-value-xor` | Fix `value`/`externalValue` mutual exclusion | C# XML `<example>` tag or Swashbuckle filter |
| `no-stack-traces` | Remove stack traces from example objects | C# XML `<example>` tag — never touch the schema |

### ASK — Present proposed change, wait for approval before editing any file

Present every ASK issue in this exact format:
```
Issue: [rule-id] — [short description]
Location: [C# file, line if known]
Proposed fix:
  [exact C# code change]
Apply this fix? (yes / no / skip all remaining ASK items)
```

If the developer says **yes** → apply to the C# source file.
If **no** or **skip** → mark as "deferred — developer must resolve manually" and continue.

### API CONTRACT CHANGES — Always ASK with full explanation before touching

Never apply silently. For any of the items below, stop and present the change to the developer first:

```
⚠️  API Contract Change — [rule-id]
What will change : [exact field / path / schema that changes]
Impact           : [what breaks — generated clients, Apigee routing, consumers]
Proposed fix     : [exact change to C# or JSON]
Apply this change? (yes / no)
```

Items that require this treatment:
- Existing request body schemas (fields, types, required arrays)
- Existing response body schemas (fields, types, required arrays)
- Existing path templates (`/api/ia/v1/...`)
- Existing HTTP method assignments (POST, GET, etc.)
- Existing security requirements already in the spec
- Any property already functioning in Apigee

Only apply after explicit developer approval.

## Workflow

1. **Read** `docs/api/swagger.json` in full.
2. **Read** `.claude/skills/validate-swagger/data/swagger-rules.json` — validate every rule where `"isActive": true`.
3. **Check** the existing compliance filters — mark rules they already cover as `COVERED`.
4. **Validate** all active rules. Work CRITICAL → HIGH → MEDIUM → LOW.
5. **Produce the report** (format below) with all violations grouped by severity.
6. **Apply AUTO fixes** immediately after the report — describe each change made and which file was edited (C# or JSON).
7. **For each ASK fix** (CRITICAL and HIGH first, then MEDIUM/LOW): present the proposed change and wait for developer approval before editing any file.
8. **After all fixes:** print the final verdict.

After C# fixes: run `dotnet build` → regenerates `docs/api/swagger.json` → re-run `/validate-swagger` to confirm.
After direct JSON fixes: re-run `/validate-swagger` immediately without rebuilding.

## Rules Reference

### 🔴 CRITICAL — 13 rules (blocking)

| Rule ID | What to check | Fix approach |
|---|---|---|
| `operation-id-missing` | Every operation must have `operationId` | C#: `[SwaggerOperation(OperationId = "...")]` on controller action |
| `required-success-response` | Every operation must have at least one 2xx response | C#: `[ProducesResponseType(...)]` on controller action |
| `response-code-range` | All status codes must be valid RFC 9110 values (100–599) | C#: `[ProducesResponseType(...)]` — remove invalid codes |
| `method-semantics` | GET/HEAD must not have request bodies; DELETE must not return 200 with body unless documented | C#: fix controller routing attributes |
| `path-params-required` | Every `{param}` in the path must have `required: true` | C#: `IOperationFilter` in `SwaggerExtensions.cs` |
| `request-body-validation` | GET/HEAD/DELETE must not define `requestBody`; POST/PUT/PATCH that accept bodies must define one | C#: controller `[HttpMethod]` + `[FromBody]` attributes |
| `content-type-header` | Every response with a body must include a `Content-Type` header declaration | C#: `[Produces("application/json")]` on controller |
| `array-items-required` | Every schema with `"type": "array"` must define `items` | C#: DTO class — or `ArraySchemaFilter` already handles this, verify coverage |
| `discriminator-property-exists` | If schema uses `discriminator.propertyName`, that property must exist in `properties` | C#: fix DTO class |
| `schema-structure-required` | Every schema must have `type`, `properties`, `allOf`/`oneOf`/`anyOf`, or `$ref` | C#: fix DTO class |
| `parameter-schema-required` | Every parameter must have either `schema` or `content`, not both, not neither | C#: controller / `IOperationFilter` |
| `security-schemes-defined` | Every name in `security` requirements must reference a scheme in `components/securitySchemes` | C#: `SwaggerExtensions.cs` → `AddSecurityDefinition` |
| `array-constraints` | Array properties must have `minItems` and `maxItems` | C#: `ArraySchemaFilter.cs` already exists — verify it covers the failing property |

All CRITICAL rules → **ASK** policy (apply with C# first, JSON fallback).

## C# Fix Patterns

### `operationId` — `operation-id-missing`, `operation-id-format`
```csharp
using Swashbuckle.AspNetCore.Annotations;

[SwaggerOperation(OperationId = "inquirePractitionerInsurance")]
[HttpPost("inquiry")]
public async Task<IActionResult> Inquiry(...)
```

### Operation description — `operation-description`
```csharp
/// <summary>
/// Retrieve the active medical malpractice insurance policy for a practitioner.
/// </summary>
/// <remarks>
/// Returns the current active policy including coverage limits, policy number, and validity period.
/// Returns 404 if no active policy exists for the given practitioner ID.
/// </remarks>
```

### Parameter description — `parameter-description`
```csharp
/// <param name="request">Insurance inquiry containing the practitioner licence number and policy filters.</param>
/// <param name="cancellationToken">Propagates notification that the operation should be cancelled.</param>
```

### `x-timeout` — `endpoint-timeout`
Create `Infrastructure/Swagger/Filters/TimeoutOperationFilter.cs`:
```csharp
using Microsoft.OpenApi.Any;
using Microsoft.OpenApi.Models;
using Swashbuckle.AspNetCore.SwaggerGen;

namespace IADataEnquiry.Infrastructure.Swagger.Filters;

public class TimeoutOperationFilter : IOperationFilter
{
    public void Apply(OpenApiOperation operation, OperationFilterContext context)
    {
        operation.Extensions["x-timeout"] = new OpenApiInteger(30000);
    }
}
```
Register in `SwaggerExtensions.cs`: `c.OperationFilter<TimeoutOperationFilter>();`

### `x-languages` — `language-support`
Create `Infrastructure/Swagger/Filters/LanguagesSchemaFilter.cs`:
```csharp
using Microsoft.OpenApi.Any;
using Microsoft.OpenApi.Models;
using Swashbuckle.AspNetCore.SwaggerGen;

namespace IADataEnquiry.Infrastructure.Swagger.Filters;

public class LanguagesSchemaFilter : ISchemaFilter
{
    public void Apply(OpenApiSchema schema, SchemaFilterContext context)
    {
        if (schema.Type == "string")
            schema.Extensions["x-languages"] = new OpenApiArray
            {
                new OpenApiString("en"),
                new OpenApiString("ar")
            };
    }
}
```
Register in `SwaggerExtensions.cs`: `c.SchemaFilter<LanguagesSchemaFilter>();`

### Server environments — `server-environments-required`
```csharp
c.AddServer(new OpenApiServer { Url = "https://localhost:44355",       Description = "Local" });
c.AddServer(new OpenApiServer { Url = "https://ia-inquiry.devclan.io", Description = "Development" });
c.AddServer(new OpenApiServer { Url = "https://REPLACE.qaclan.io",     Description = "Testing" });
c.AddServer(new OpenApiServer { Url = "https://REPLACE.leanstg.com",   Description = "Staging" });
c.AddServer(new OpenApiServer { Url = "https://REPLACE.lean.sa",       Description = "Production" });
```
Note: `REPLACE` URLs must be confirmed with the infrastructure team before applying.

### `Idempotency-Key` header — `idempotency-key`
```csharp
public class IdempotencyKeyOperationFilter : IOperationFilter
{
    public void Apply(OpenApiOperation operation, OperationFilterContext context)
    {
        var method = context.ApiDescription.HttpMethod?.ToUpperInvariant();
        if (method is "POST" or "PATCH")
        {
            operation.Parameters ??= new List<OpenApiParameter>();
            operation.Parameters.Add(new OpenApiParameter
            {
                Name = "Idempotency-Key",
                In = ParameterLocation.Header,
                Required = false,
                Description = "Client-generated UUID to guarantee exactly-once processing.",
                Schema = new OpenApiSchema { Type = "string", Format = "uuid" }
            });
        }
    }
}
```

### `API-Version` versioning header — `versioning-headers`
```csharp
operation.Responses.ToList().ForEach(r =>
{
    r.Value.Headers ??= new Dictionary<string, OpenApiHeader>();
    r.Value.Headers["API-Version"] = new OpenApiHeader
    {
        Description = "The API version that processed this request.",
        Schema = new OpenApiSchema { Type = "string", Example = new OpenApiString("v1") }
    };
});
```

## Pass / Fail Criteria

| Condition | Result |
|---|---|
| Any unresolved CRITICAL issue | ❌ BLOCKED |
| Any unresolved HIGH issue | ❌ BLOCKED |
| MEDIUM or LOW issues only | ✅ PASSED (issues noted, non-blocking) |
| All issues resolved | ✅ PASSED |

A deferred issue (developer said no/skip to an ASK) still counts as unresolved for the verdict.
